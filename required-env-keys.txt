# required-env-keys.txt — keys the PROD stack cannot run without (SERV-173)
#
# One key NAME per line. Every key here must reach /opt/construct-server/.env with a
# non-empty value, or deploy.yml fails before it pulls or recreates anything
# (scripts/assert-env-keys.sh). Names only: this file holds nothing worth protecting
# and is reviewed like any other.
#
# What belongs here: every key the stack READS whose loss would be silent. Compose's
# `${KEY:-}` defaults mean a dropped credential does not fail — the service boots with
# the feature off, healthy — which is how LYCEUM_BINDERY_API_KEY went missing four
# times. A key that may legitimately be blank does NOT belong here; an empty value is
# not a value (CLAUDE.md) and is reported as missing.
#
# What does not: the image pins (versions.env owns them and git delivers them), and
# keys nothing reads — assert-env-keys.sh names those as "unlisted" on every deploy,
# which is the prompt to either add them here or retire them from the vault.
#
# ORDER OF OPERATIONS when adding a key — vault first, then this file:
#   signet set --project construct-server --name KEY
#   signet target add-key --project construct-server --gh-secret PROD_ENV_FILE --name KEY
#   signet sync
#   ./scripts/assert-env-keys.sh --vault      # proves the next deploy will carry it
#   …then add the line below and merge. The other order blocks every prod deploy,
#   rollbacks included, until the vault catches up.
