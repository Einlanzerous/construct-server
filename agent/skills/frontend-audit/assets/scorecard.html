FrontendNote

Should this become a skill?

Yes: a quarterly audit skill

Package this run as an estate skill (frontend-audit). It holds the rubric, the Firefox-first rule, the fan-out across active Switchyard projects plus the extra targets file, and a refresh of this page. Run it each quarter as a scheduled routine. It should file one ticket per high-priority fix in the owning project and record the scores, so the next run shows movement. The guidance itself changes slowly, so quarterly is often enough.

For UI PRs: a checklist, not a skill

A full audit per PR costs too much and reads too broadly. Instead, add a short "Frontend" block to each frontend repo's REVIEW.md for the CI reviewer to apply to diffs that touch .vue or .css:

  • Motion gated on prefers-reduced-motion
  • Modals on <dialog>/showModal(), not a div scrim
  • Enter handlers guard isComposing
  • No outline: none without a :focus-visible ring
  • New CSS features are in Firefox, or behind @supports
  • No ::-webkit- rule without its standard property

Do first, once, everywhere

  • Add a Baseline line to every frontend's CLAUDE.md: "Firefox is the primary browser; target Baseline Widely available plus current Firefox ESR." This one line steers every future agent edit.
  • A global reduced-motion reset in each app's base CSS.
  • A Firefox project in Playwright where e2e already exists.
  • Self-host Google Fonts (Catenary, Drydock, Interlock, Centrifuge).
How this was scored, and what it missed

The rubric comes from developer.chrome.com/docs/modern-web-guidance: the hub, getting started, the modernization workflow, and the guide catalog. Individual guide pages were not read. Six reviewer agents read each frontend's source, CLAUDE.md and build config, and grepped for the guidance's legacy patterns. None ran a browser, Lighthouse, or the guidance's own legacy-scan CLI. Its install was blocked in this session (replace with the run's actual legacy-scan outcome), so the legacy column is a manual approximation. Scores are judgment calls, not measurements. Plimsoll was audited from code alone, and no data was read. Targets with no persistent checkout were read from a fresh clone of main.
